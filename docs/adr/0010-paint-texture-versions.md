# ADR 0010: Покраска 3D-моделей — версионные текстуры, оригинал неизменяем

- **Статус:** принято (2026-11-22, решение человека)
- **Контекст:** см. `ARCHITECTURE.md`, раздел 12 (вопрос 8)

## Контекст

Модуль покраски — ключевая функция 3DPAINT. Пользователь должен рисовать
прямо на 3D-модели в интерактивном предпросмотре (Three.js). Нужно решить,
как хранить результат: перезаписывать модель, хранить её копию или хранить
только текстуру.

Требования, зафиксированные человеком:
- рисование в браузере поверх модели (raycast → UV → canvas-текстура);
- результат сохраняется в текстурах модели;
- оригинальная модель не должна теряться; каждая сохранённая покраска — новая
  версия;
- первая версия AI-сервиса — заглушка, к покраске отношения не имеет.

## Решение

1. **Рисование на клиенте.** Three.js: raycast по модели → UV-координаты
   точки попадания → 2D-отрисовка на canvas-текстуре. Инструменты: кисть
   (цвет, размер), ластик, undo/redo. Модуль `frontend/src/features/paint`.

2. **Хранение — версионные текстуры.** Текстуры лежат в S3 отдельными
   объектами: `{ownerId}/{modelId}/textures/v{N}/baseColor.png`.
   В БД Models — сущность `ModelTexture (Id, ModelId, Version, Kind,
   ObjectKey, CreatedAt)`. Оригинальный файл модели **никогда не
   перезаписывается**; каждая сохранённая покраска создаёт новую версию
   текстуры.

3. **API Models** (владельцам):
   - `GET /api/models/{id}/textures` — список версий;
   - `POST /api/models/{id}/textures` → `{textureId, version, uploadUrl}`
     (presigned PUT);
   - `POST /api/models/{id}/textures/{textureId}/complete` — подтверждение
     загрузки, публикация `TextureUpdated` (Outbox).

4. **Processing пересобирает GLB.** Консьюмер `TextureUpdated` применяет
   новую текстуру к GLB, сохраняет пересобранный GLB (новый ассет) и
   обновлённое превью, публикует `ModelProcessed`. Так превью в списке
   всегда показывает актуальную (раскрашенную) модель.

5. **Модели без UV.** Покраска по UV невозможна. Варианты: авто-развёртка в
   Processing (`xatlas`), запрет покраски, другой подход. **Вопрос вынесен
   человеку** (ARCHITECTURE.md §12, п. 13) и не реализуется до его решения.

## Последствия

- Плюс: история покрасок, откат на любую версию, оригинал всегда доступен;
  загрузка текстуры (PNG, несколько МБ) идёт presigned-путём, не нагружая
  сервисы.
- Плюс: контракт (`TextureUpdated`) расширяет существующую событийную модель
  Models ↔ Processing без новых синхронных зависимостей.
- Минус: нужно хранить и пересобирать GLB на каждую версию (трафик S3 и
  время обработки растут с числом сохранений).
- Минус: без UV-развёртки часть моделей для покраски непригодна — решение
  ожидается.
- Реализация — Фаза 6.5 плана (после Фазы 6, когда есть Processing и
  контракты событий).
