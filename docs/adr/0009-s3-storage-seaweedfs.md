# ADR 0009: Хранилище файлов — S3-совместимое (SeaweedFS в dev)

- **Статус:** принято (2026-11-22, решение человека)
- **Супersed/связано:** уточняет ADR 0003 (прямая загрузка по presigned URL)

## Контекст

- Образ `minio/minio` удалён из Docker Hub (pull 404), `quay.io/minio/minio`
  требует авторизации, `bitnami/minio` недоступен — чистый `docker compose up`
  не поднимается (TD-14, блокер).
- Задача требует, чтобы код работал с **любым** S3-совместимым хранилищем:
  endpoint, регион, ключи и имя бакета — только из конфигурации.

## Решение

1. В dev используется **SeaweedFS в S3-режиме**: образ
   `chrislusf/seaweedfs:4.54` (тег **зафиксирован**, не `latest`), команда
   `server -s3 -s3.port=9000 -dir=/data` (S3 API на 9000, Filer UI на 8888).
2. В Docker Compose имя сервиса остаётся нейтральным — **`storage`**.
3. В `ARCHITECTURE.md` все упоминания «MinIO» заменены на
   «S3-совместимое хранилище (SeaweedFS в dev)».
4. Код (монолит, затем Model Service) не знает о SeaweedFS: S3-клиент
   настраивается только из конфигурации:
   - `Minio__Endpoint`, `Minio__AccessKey`, `Minio__SecretKey`,
     `Minio__BucketName`, `Minio__Region` (регион необязательный — ставится
     в клиент, только если задан), `Minio__UseSsl`.
   - Имена переменных окружения сохраняются как исторические
     (`MINIO_ROOT_USER`, `MINIO_BUCKET` и т.д.), чтобы не ломать существующие
     `.env`; в целевой системе новые сервисы назовут их нейтрально.
5. Имя бакета — `userdata` (строчное, валидное имя S3-бакета); было
   `USERDATA` в `.env.example` — невалидно, загрузка падала с 500 (TD-2).

## Последствия

- Плюс: чистый `docker compose up` работает на свежем клоне без внешних
  реестров; переход на другое S3-хранилище в проде = смена переменных
  окружения, а не кода.
- Плюс: SeaweedFS поддерживает presigned URL (GET/PUT), что проверено
  в baseline (Фаза 0).
- Минус: SeaweedFS без отдельного S3-auth-конфига принимает любые
  доступ/секрет-ключи — приемлемо для dev; в проде (реальное S3)
  credentials проверяются хранилищем.
- Минус: нет MinIO Console; для ручного просмотра объектов в dev доступен
  Filer UI (127.0.0.1:8888).
