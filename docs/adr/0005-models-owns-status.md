# ADR 0005: Models Service — единственный владелец статуса модели

- **Статус:** принято (2026-11-22, формализация)

## Контекст

Многие сервисы знают о модели (Models, Processing, AI, Gateway/Frontend).
Нужна одна точка, где хранится и изменяется статус жизненного цикла модели
(`Uploaded → Processing → Ready | Failed`, `AiJob*`).

## Решение

Все изменения статуса пишет **только** Model Service (в свою БД). Остальные
сервисы публикуют события, а Models применяет их по правилам.

## Последствия

- Плюс: одна точка записи, простая консистентность, понятная история.
- Минус: Models становится ключевым узлом — нужен Outbox и идемпотентные
  обработчики событий.
