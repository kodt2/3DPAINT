# ADR 0014: Доверенная загрузка GLB в 3D-вьюере (шаг 3c.3)

- **Статус:** принято (2026-11-26, шаг 3c.3); дополнено в шаге 3c.5 (2026-11-25) — локальные декодеры (раздел 2)

## Контекст

3D-вьюер `/spa/models/{id}` открывает пользовательские GLB-файлы из S3.
GLB — недоверенный ввод: в нём могут быть внешние URI (текстуры,
доступники к buffer-ам), сжатые геометрии, огромные буферы. При этом сам
presigned URL, по которому файл скачивается, — артефакт нашей системы
(выдаёт его монолит), а значит — доверенный.

Требования:

- никаких внешних запросов из GLB-парсинга (нет CDN, нет «скачать
  текстуру с url из файла»);
- Draco/Meshopt — без CDN-WASM (AGENTS.md: автономность);
- прогресс загрузки и отмена при уходе со страницы;
- истёкший presigned URL не должен ломать вьюер.

## Решение

### 1. Два доверенных уровня

- **Транспорт доверен:** браузер `fetch`-ит presigned URL напрямую
  (S3-CORS настроен на origins SPA, `S3_CORS_ORIGINS`), тело читается
  потоково (`response.body` + reader, прогресс по `content-length`).
  `fetch` идёт по URL, который выдал наш API, — это не недоверенный ввод.
- **Содержимое недоверенно:** парсинг — `GLTFLoader.parse(arrayBuffer)`
  с собственным `LoadingManager`, у которого `setURLModifier` пропускает
  только `blob:` и `data:` и бросает исключение на любом другом URI.
  Внешний URI внутри GLB → parse падает с явным сообщением; `<img>` и
  любой сетевой запрос по URI из файла не создаются (проверено тестом:
  `document.createElementNS` для `img` не вызывается, `material.map ===
  null` — three r187 глотает ошибку отдельной текстуры, поэтому
  наблюдаемые гарантии — именно «нет запроса» и «текстура null»).

### 2. Сжатые форматы: локальные декодеры без CDN (шаг 3c.5)

GLB с Draco/Meshopt/KTX2 (BasisU) декодируются. Все ассеты декодеров —
локальные копии из `node_modules/three` (r187): `scripts/sync-decoders.mjs`
копирует их в `public/assets/decoders/three-<версия-three>/` (hook `predev`/`prebuild`), nginx отдаёт их из `/assets/decoders/**` с immutable-кэшем, Gateway маршрутизирует `/assets/{**}` на frontend. В URL — версия three: апгрейд three = новые ассеты без старого кэша. CDN и сторонние origin не используются; доверенный `LoadingManager` (§1) дополнительно разрешает только этот локальный префикс (и `blob:`/`data:`).

**Ленивая загрузка.** Перед парсингом вьюер читает JSON-чанк GLB
(`readGlbJson`, свой парсер контейнера: magic, версия, длина, chunk-типы)
и только по наличию расширений (`KHR_draco_mesh_compression`,
`EXT_meshopt_compression`, `KHR_texture_basisu`) динамически импортирует
чанк `glb-decoders.ts` и ставит ровно нужные декодеры. Обычный GLB чанк
не получает вовсе (~95 КБ gzip).

**Каждый декодер** (three r187):
- **Draco** — `DRACOLoader` с `setDecoderPath` в объектной форме
  (`{js, wasm}` на локальные `draco/gltf/*` — именно glTF-сборка, не
  standalone). Объектная форма оставляет `dep_js = null`: чистый JS-
  fallback (~700 КБ) не запрашивается, WebAssembly обязателен. Пул
  воркеров стартует `preload()` до декодирования; `dispose()` завершает
  воркеров.
- **Meshopt** — `meshopt_decoder.module.js`: wasm встроен в JS (base64),
  воркеры по Blob-URL, сетевых запросов нет. В three r187 у пула нет
  `dispose` — воркеры живут до перезагрузки страницы (TD-29).
- **KTX2** — `KTX2Loader` с `setTranscoderPath` на локальный `basis/`.
  `detectSupport()` требует renderer: вьюер пробирает возможности
  GPU-текстур через одноразовый WebGL-контекст (паттерн `webgl.ts`),
  синхронно читает их и сразу `loseContext()`.

**Диагностика.** `extensionsRequired` с расширением вне списка
поддерживаемых (`SUPPORTED_GLTF_EXTENSIONS`, сверен со списком
`GLTFLoader` r187) → файл отклоняется до парсинга с расширением в
сообщении (`kind: 'unsupported-extension'`). Ошибки декодирования
сжатых данных — отдельный `kind: 'compression'` (отличается от
повреждённого контейнера). Фаза декодирования ограничена таймаутом
(`DECODE_TIMEOUT_MS = 60 с`, отдельно от времени скачивания):
таймаут/отмена → `decode-timeout`/`aborted`, декодеры диспозятся. Сервис
`inspect-glb.mjs` (`npm run inspect:glb <файл>`) диагностирует GLB без
зависимостей (magic/версия/длина/чанки, расширения, число вершин и
треугольников, флаки draco/meshopt/ktx2).

Фикстуры тестов (Draco/Meshopt/Meshopt+quant) генерируются в памяти
(`src/test/gltf-fixture.ts` через `@gltf-transform` + `draco3dgltf` +
`meshoptimizer`), бинарных файлов в репозитории нет. E2E проверяет:
рендер трёх сжатых форматов, локальность запросов декодера
(только origin SPA + presigned S3), отсутствие утечки GPU-ресурсов
при перемонтировании Draco-сцены и отклонение неподдерживаемого
расширения.

### 3. Один повтор при истёкшем/сломном URL

Ошибка `fetch` (http или сеть) → один повтор: новый `GET /api/models/{id}`
(свежий presigned URL) и повторная загрузка. Второй сбой — ошибка
«не удалось загрузить файл». Abort при размонтировании (уход со страницы)
— `kind: 'aborted'`, UI-ошибкой не считается.

### 4. GPU-гигиена и смена сцен

- При размонтировании сцены — `disposeSceneObject(root)`: traverse +
  `dispose()` геометрий/материалов/текстур (E2E проверяет, что
  `renderer.info.memory.geometries` не растёт при повторном входе).
- Навигация между моделями — `key={id}` на компоненте: состояние
  (прогресс, ошибки, контекст) стартует с нуля без ручного сброса.
- Потеря WebGL-контекста (`webglcontextlost`, `preventDefault()`) —
  оверлей с «Перезагрузить сцену» (пересоздание Canvas). Нет WebGL —
  уведомление без canvas.

### 5. Крупные файлы

Отдельного лимита вьюера нет: максимальный размер определяется upload
монолита (500 МБ, TD-13). Проверка крупного файла: GLB ~51.5 МБ
(2.5M вершин, 2M треугольников) генерируется в памяти (`buildLargeGlb`) —
стриминг с прогрессом и parse проходят за < 1 с на dev-машине; бинарных
фикстур в репозитории нет.

## Последствия

- Внешний URI в GLB не становится вектором exfiltration/SSRF из
  браузера: транспорт (fetch) и парсер (parse + URL modifier) разделены;
  декодеры — только локальные ассеты того же origin.
- Реальные модели со сжатием (Blender Draco-экспорт, веб-оптимизаторы
  Meshopt) открываются; TD-26 закрыт. Не открывается только то, чего
  three r187 не умеет или что требует неизвестного расширения — с
  диагностикой (имя расширения в сообщении).
- В three r187 `new URL(..., import.meta.url)` в DRACOLoader
  (дефолтные пути декодера) Vite выносит в `dist/assets/**` как
  отдельные файлы (~1.2 МБ); на них никто не ссылается, т.к. пути
  переопределяются `setDecoderPath` — мёртвый вес в сборке, осознанно
  оставлен (устранилось бы только форком/патчем three).
- Meshopt-воркеры не терминируются до перезагрузки страницы (ограничение
  three r187) — TD-29.
- В Фазе 5 (Models Service) модель доверия не меняется: presigned URL
  по-прежнему выдаёт наш сервис, контент по-прежнему недоверенный.
- Headless Chromium (Playwright): WebGL2 доступен из коробки
  (SwiftShader), дополнительные флаги не понадобились.
