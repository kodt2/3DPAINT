# ADR 0014: Доверенная загрузка GLB в 3D-вьюере (шаг 3c.3)

- **Статус:** принято (2026-11-26, шаг 3c.3)

## Контекст

3D-вьюер `/spa/models/{id}` открывает пользовательские GLB-файлы из S3.
GLB — недоверенный ввод: в нём могут быть внешние URI (текстуры,
доступники к buffer-ам), сжатые геометрии, огромные буферы. При этом сам
presigned URL, по которому файл скачивается, — артефакт нашей системы
(выдаёт его монолит), а значит — доверенный.

Требования:

- никаких внешних запросов из GLB-парсинга (нет CDN, нет «скачать
  текстуру с url из файла»);
- Draco/Meshopt — без CDN-WASM (AGENTS.md: автономность);
- прогресс загрузки и отмена при уходе со страницы;
- истёкший presigned URL не должен ломать вьюер.

## Решение

### 1. Два доверенных уровня

- **Транспорт доверен:** браузер `fetch`-ит presigned URL напрямую
  (S3-CORS настроен на origins SPA, `S3_CORS_ORIGINS`), тело читается
  потоково (`response.body` + reader, прогресс по `content-length`).
  `fetch` идёт по URL, который выдал наш API, — это не недоверенный ввод.
- **Содержимое недоверенно:** парсинг — `GLTFLoader.parse(arrayBuffer)`
  с собственным `LoadingManager`, у которого `setURLModifier` пропускает
  только `blob:` и `data:` и бросает исключение на любом другом URI.
  Внешний URI внутри GLB → parse падает с явным сообщением; `<img>` и
  любой сетевой запрос по URI из файла не создаются (проверено тестом:
  `document.createElementNS` для `img` не вызывается, `material.map ===
  null` — three r187 глотает ошибку отдельной текстуры, поэтому
  наблюдаемые гарантии — именно «нет запроса» и «текстура null»).

### 2. Draco/Meshopt не устанавливаются

Локальная WASM-копия декодеров в этом шаге не вводится (нет в
`node_modules`, CDN запрещён). GLB со сжатой геометрией → parse-ошибка →
`GlbLoadError { kind: 'compression' }` → честное сообщение «модель
использует сжатие, которое вьюер не поддерживает». Ограничение зафиксировано
в TECH_DEBT (TD-26).

### 3. Один повтор при истёкшем/сломном URL

Ошибка `fetch` (http или сеть) → один повтор: новый `GET /api/models/{id}`
(свежий presigned URL) и повторная загрузка. Второй сбой — ошибка
«не удалось загрузить файл». Abort при размонтировании (уход со страницы)
— `kind: 'aborted'`, UI-ошибкой не считается.

### 4. GPU-гигиена и смена сцен

- При размонтировании сцены — `disposeSceneObject(root)`: traverse +
  `dispose()` геометрий/материалов/текстур (E2E проверяет, что
  `renderer.info.memory.geometries` не растёт при повторном входе).
- Навигация между моделями — `key={id}` на компоненте: состояние
  (прогресс, ошибки, контекст) стартует с нуля без ручного сброса.
- Потеря WebGL-контекста (`webglcontextlost`, `preventDefault()`) —
  оверлей с «Перезагрузить сцену» (пересоздание Canvas). Нет WebGL —
  уведомление без canvas.

### 5. Крупные файлы

Отдельного лимита вьюера нет: максимальный размер определяется upload
монолита (500 МБ, TD-13). Проверка крупного файла: GLB ~51.5 МБ
(2.5M вершин, 2M треугольников) генерируется в памяти (`buildLargeGlb`) —
стриминг с прогрессом и parse проходят за < 1 с на dev-машине; бинарных
фикстур в репозитории нет.

## Последствия

- Внешний URI в GLB не становится вектором exfiltration/SSRF из
  браузера: транспорт (fetch) и парсер (parse + URL modifier) разделены.
- Часть реальных моделей (с Draco/Meshopt) временно не открывается —
  осознанное ограничение (TD-26), не баг.
- В Фазе 5 (Models Service) модель доверия не меняется: presigned URL
  по-прежнему выдаёт наш сервис, контент по-прежнему недоверенный.
- Headless Chromium (Playwright): WebGL2 доступен из коробки
  (SwiftShader), дополнительные флаги не понадобились.
