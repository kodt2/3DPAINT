# ADR 0012: .NET 10 (LTS) для новых сервисов

- Дата: 2026-11-22
- Статус: принято (решение человека)

## Контекст

Монолит написан на .NET 8 (LTS до ноября 2026, с этого момента std). Новые микросервисы
начинаем писать с нуля — у нас нет причин наследовать устаревающую платформу.

## Решение

1. Все **новые** .NET-сервисы (`services/*`) пишутся на **.NET 10 (LTS)**, target framework `net10.0`.
2. **Монолит** (`legacy/monolith`) остаётся на **.NET 8** (`net8.0`) без изменений до его
   удаления на Фазе 10. Обновление монолита — отдельная задача, если понадобится.
3. Пин SDK: отдельный `global.json` в каталоге каждого .NET-сервиса (SDK выбирает его,
   поднимаясь от каталога проекта). Корневой `global.json` (8.0.x) действует для монолита.
4. Docker-образы: `mcr.microsoft.com/dotnet/sdk:10.0` (сборка) и `mcr.microsoft.com/dotnet/aspnet:10.0`
   (runtime) для новых сервисов; `sdk:8.0`/`aspnet:8.0` — только для монолита.
5. `Makefile` держит два SDK-образа: `DOTNET_SDK_8_IMG` (монолит) и `DOTNET_SDK_10_IMG` (gateway и дальше).

## Следствия

- YARP обновлён 2.2.0 → **2.3.0** (последняя стабильная, совместима с net10.0; поведение
  «h2c по умолчанию к http-апстриму» сохранено — у нас протокол зафиксирован на HTTP/1.1).
- Тесты gateway: `Microsoft.AspNetCore.Mvc.Testing` 10.0.x, `Microsoft.NET.Test.Sdk` 18.x.
- Временное (до Фазы 10) в стеке будут жить два поколения рантаймов — это осознанно:
  монолит — временный и не трогаем его (золотое правило 3).
