# ADR 0013: Маршрут /api/models и owner-scoped доступ в монолите (до Фазы 5)

- **Статус:** принято (2026-11-24, шаг 3c.2)

## Контекст

Шаг 3c.2 — SPA-библиотека: список моделей, presigned-превью, пагинация,
удаление. До Фазы 5 хранилище и доступ к моделям отдаёт монолит, а не
будущий Models Service. Нужен JSON-эндпоинт для SPA, который:

- совпадает с целевой архитектурой (чтобы в Фазе 5 менялся только
  бэкенд, а не контракт);
- не ломает существующие Razor-эндпоинты (`/api/files/**`);
- не раскрывает чужие модели и внутреннее устройство (S3-ключи,
  внутренние хосты, данные владельца).

## Решение

### 1. Маршрут — `/api/models`

- `GET /api/models?page={n}&pageSize={n}` — страница моделей пользователя;
  `pageSize` — от 1 до 100 (дефолт 20), нарушение — `400` ProblemDetails.
- `GET /api/models/{id}` — детальная карточка (presigned `thumbnailUrl`
  и `downloadUrl`); чужой или несуществующий `id` — `404`.
- `DELETE /api/models/{id}` — удаление записи и S3-объектов (оригинал +
  thumbnail); повторный `DELETE` — `404` (идемпотентность).

Путь выбран **совпадающим с целевым API из ARCHITECTURE.md §7.2**: в Фазе 5
Gateway перенаправит `/api/models` на Models Service, фронтенд
`frontend/src/api/models.ts` и сгенерированные OpenAPI-типы не меняются.

### 2. Owner-check — в SQL, а не в коде после запроса

Чтение и удаление фильтруются одним условием:
`WHERE id = @id AND user_id = @userId`. Чужой `id` неотличим от
несуществующего — всегда `404`, никогда `403` (без утечки «модель
существует, но не твоя»). Список строится только с
`WHERE user_id = @userId`.

### 3. Чистота DTO

`ModelDto` / `ModelDetailDto` содержат ровно: `id`, `name`, `sizeBytes`,
`createdAt` и presigned URL (`thumbnailUrl`, для детальной карточки ещё
`downloadUrl`). **Не содержат**:

- внутренний host хранилища (`storage:9000` — имя сервиса в compose);
  presigned URL — по публичному эндпоинту (`PublicEndpoint`/
  `S3_PUBLIC_PORT`, см. TD-3);
- внутренние S3-ключи объектов отдельным полем (ключ есть только внутри
  подписанного URL — это и есть публичный артефакт);
- данные владельца (`user_id`, `login`, `fullName` и т.п.).

Проверка зашита в E2E (`e2e/library.spec.ts`): whitelist полей элемента
страницы + отрицательные проверки по сырому JSON.

### 4. Удаление: сначала S3, потом БД

`DELETE` сначала удаляет S3-объекты (оригинал и thumbnail; удаление
отсутствующего объекта — no-op), затем строку из БД и отвечает `204`.
При ошибке S3 — `500`, запись остаётся, повтор `DELETE` безопасен
(S3-часть уже идемпотентна). Обратный порядок (сначала БД) терял бы файлы
при сбое между шагами.

## Последствия

- `/api/files/**` (Razor-UI) продолжает работать без изменений; оба
  маршрута живут в монолите до Фазы 5.
- Фронтенд получает типизированный клиент из OpenAPI; смена бэкенда в
  Фазе 5 прозрачна при сохранении контракта.
- Presigned URL живут `PresignedUrlExpiryMinutes` (дефолт 30 минут):
  SPA один раз переподгружает список при истёкшем превью (шаг 3c.2).
