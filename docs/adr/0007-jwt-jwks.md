# ADR 0007: JWT (RS256) + JWKS, локальная валидация

- **Статус:** принято (2026-11-22, формализация)

## Контекст

Каждому сервису нужно проверять, кто пользователь. Если каждый запрос
уходит в Auth Service на валидацию — Auth становится узким местом и
одной точкой отказа для всего трафика.

## Решение

Auth Service выпускает JWT, подписанный **асимметричным** ключом (RS256).
Публичный ключ публикуется по JWKS-эндпоинту; остальные сервисы и Gateway
валидируют токен **локально** (подпись, срок, issuer/audience).

## Последствия

- Плюс: Auth не в пути каждого запроса; сервисы автономны.
- Минус: окно жизни токена = окно отозванности (для dev — приемлемо, срок
  60 мин по текущему монолиту); нужен обмен ключами (ротация — позже, при
  необходимости).
