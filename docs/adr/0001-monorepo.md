# ADR 0001: Монорепозиторий

- **Статус:** принято (2026-11-22, формализация; решение зафиксировано в ARCHITECTURE.md §11)

## Контекст

Команда небольшая (фактически один разработчик). Сервисы, контракты событий и
фронтенд тесно связаны: изменение контракта часто требует синхронной правки
двух-трёх проектов.

## Решение

Один репозиторий (monorepo) для всех сервисов, контрактов, фронтенда и
инфраструктуры. Структура — по целевой схеме в `ARCHITECTURE.md` и `AGENTS.md`
(раздел 3).

## Последствия

- Плюс: атомарные кросс-сервисные изменения, общие контракты в одном месте,
  единый CI.
- Минус: репозиторий растёт; дисциплина по границам пакетов/каталогов
  обязательна (правила в `AGENTS.md`).
